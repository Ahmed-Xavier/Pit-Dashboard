# Pit widget topic and service map

The only UI interface names are in [`../config/topics.json`](../config/topics.json). The names and types below were verified against publisher/subscriber/service declarations in the simulation source. A live ROS graph was unavailable in this Windows session, so runtime presence and message arrival remain to be confirmed in WSL.

| Widget/action | ROS interface | Type | Source status |
|---|---|---|---|
| LiDAR telemetry | `/scan` | `sensor_msgs/msg/LaserScan` | OK: Gazebo bridge remaps lidar scan to `/scan` |
| GPS fix | `/fix` | `sensor_msgs/msg/NavSatFix` | OK: Gazebo bridge remaps navsat to `/fix` |
| Map position and speed | `/odometry/global` | `nav_msgs/msg/Odometry` | OK: localization / waypoint manager use this topic |
| Wheel speed | `/wheel/odom` | `nav_msgs/msg/Odometry` | OK: vehicle state publishes; simulation also relays odometry |
| IMU | `/imu/data` | `sensor_msgs/msg/Imu` | OK: Gazebo remaps IMU to `/imu/data`; old app expected `/esp32/imu` |
| Track progress | `/track/progress` | `std_msgs/msg/Float32` | OK only when `dashboard_bridge` is launched |
| Battery | `/vehicle/battery_percent` | `std_msgs/msg/Float32` | OK only when `dashboard_bridge` is launched; generated by its fake status node |
| Temperature | `/vehicle/temperature_c` | `std_msgs/msg/Float32` | OK only when `dashboard_bridge` is launched; generated by its fake status node |
| Waypoint list and numbered map labels | `/waypoints/markers` | `visualization_msgs/msg/MarkerArray` | OK: waypoint manager publishes; pending map clicks are reconciled with manager markers |
| ADD button, then map click | `/clicked_point` | `geometry_msgs/msg/PointStamped` | OK: waypoint manager subscribes; client publish capability required |
| START | `/waypoints/start` | `std_srvs/srv/Trigger` | OK: waypoint manager service; bridge services capability required |
| UNDO | `/waypoints/undo` | `std_srvs/srv/Trigger` | OK: waypoint manager service; bridge services capability required |
| CLEAR | `/waypoints/clear` | `std_srvs/srv/Trigger` | OK: waypoint manager service; bridge services capability required |

Former fake/invented dashboard signals (for example `/power/battery`, `/diagnostics/pi5`, `/camera/image_raw`, `/esp32/status`, and `/esp32/imu`) are not presented as live vehicle data. `/imu/data` replaces the stale IMU topic; battery/temperature use the simulation dashboard bridge's actual status topics.

Status indicators: connecting / connected / disconnected at the bridge level; each listed topic is live when a message arrived in the configured silence window, otherwise silent. Reconnect is automatic. Service interfaces must first appear in Foxglove's `advertiseServices` message.
